# Apache HTTP Method 차단 설정

Apache에서 불필요한 HTTP Method(`PUT`, `DELETE`, `OPTIONS`, `TRACE`) 요청을 차단한다.

현재 구성은 Apache(Web) → Tomcat(WAS) 구조이며, Apache 단계에서 불필요한 HTTP Method를 먼저 차단하도록 설정한다.

## 1. httpd.conf 설정

설정 파일:

```bash
vi /etc/httpd/conf/httpd.conf
```

### 설정 설명
- TraceEnable Off
  - Apache의 TRACE Method를 비활성화한다.
- RewriteEngine On
  - Apache mod_rewrite 기능을 활성화한다.
- RewriteCond %{REQUEST_METHOD} ^(PUT|DELETE|OPTIONS|TRACE)$ [NC]
  - 요청 Method가 PUT, DELETE, OPTIONS, TRACE 중 하나인지 확인한다.
- RewriteRule ^ - [F]
  - 해당 요청을 403 Forbidden으로 차단한다

```vi
<IfModule jk_module>
    JkWorkersFile /etc/httpd/conf/workers.properties
    JkLogFile /var/log/httpd/mod_jk.log
    JkLogLevel info
    JkLogStampFormat "[%a %b %d %H:%M:%S %Y]"
    JkMount /*.jsp worker1
    JkMount /* worker1
</IfModule>


# 불필요 HTTP Method 차단
TraceEnable Off

RewriteEngine On
RewriteCond %{REQUEST_METHOD} ^(PUT|DELETE|OPTIONS|TRACE)$ [NC]
RewriteRule ^ - [F]
```

### 2. mod_rewrite 활성화 여부 확인
- 설정 적용 전 Apache에서 mod_rewrite 모듈이 로드되어 있는지 확인한다.
```bash
httpd -M | grep rewrite
```
- 정상적으로 활성화되어 있으면 다음과 같이 출력된다.
```
rewrite_module (shared)
```

### 3. Apache 설정 문법 확인
- Apache를 재시작하기 전에 설정 파일 문법을 확인한다.
```bash
apachectl configtest
```
- 정상이면 다음과 같이 출력된다.
```
Syntax OK
```

### 4. Apache 재시작
> reload: 프로세스를 완전히 종료하지 않고 설정만 다시 읽음. 서비스 중단이 거의 없어 일반적으로 권장
> restart: Apache 프로세스를 완전히 재시작. 순간적인 접속 끊김이 발생할 수 있음

- 설정을 적용하기 위해 Apache를 재시작한다.
```bash
systemctl restart httpd
```

- httpd.conf 변경은 보통 reload만으로 적용됩니다.
```bash
systemctl reload httpd
```

- Apache가 정상적으로 실행 중인지 확인한다.
```bash
systemctl status httpd
```


### 5. HTTP Method 차단 테스트
- Apache 자체에서 차단되는지 확인하기 위해 웹 서버 내부에서 127.0.0.1로 테스트한다. (WAF 있을시)
```bash
curl -i -X PUT     http://127.0.0.1/main.do
curl -i -X DELETE  http://127.0.0.1/main.do
curl -i -X OPTIONS http://127.0.0.1/main.do
curl -i -X TRACE   http://127.0.0.1/main.do
```
- 정상적으로 차단되면 다음과 같이 403 Forbidden 응답이 발생한다.
```
HTTP/1.1 403 Forbidden
Server: Apache
```
